# 课程 02：产品化自己，技能盘点与组合优势

> **前置课程**：[课程 01：底层认知，销售的本质](../01-底层认知/README.md)。你需要先接受一个设定：销售的第一步不是找客户，是搞清楚自己到底在卖什么。
> **预计学习时长**：10–14 小时（阅读约 3 小时，工作表、矩阵、录音与迭代约 7–11 小时）。本课不适合速读——每一课的产出物都是下节课的输入。
> **课程性质**：学院核心课。学完你手里会有一套可以直接拿去接触市场的"个人产品说明书"：三张资产清单、技能四象限、≥3 个候选组合、一版通过差异化检验的 PVP、三版电梯陈述、一份第一个证据的行动计划。

## 课程目标

学完本课程，你能够：

1. 独立完成三张资产清单（硬技能 / 软技能 / 经历资产，各 ≥ 5 条），每条符合"动词 + 对象 + 结果"格式。
2. 用四象限矩阵（市场供给 × 熟练度）给自己每项技能定位，并按象限写出对应的定价与组合策略。
3. 用"技能 × 行业 × 人群"三维矩阵法产出 ≥ 3 个候选组合，且每个都通过交叉点稀缺度三问。
4. 写出一版通过差异化检验的 PVP，并在社交场合、求职面试、客户提案三个场景各输出一版 ≤ 35 秒的电梯陈述（录音验证）。
5. 盘点自己的证据资产存量，并从三条正当路径中选定至少一条，制定 14 天内可执行的"第一个证据"行动计划。

## 第 1 课：三张资产清单——把"我"拆成可卖的零件

### 讲解

**为什么先盘点自己，再找客户？** 因为"卖给谁"的答案依赖"卖什么"：你的 ICP（见[课程 03](../03-市场与客户/README.md)）只能从你的组合优势里长出来。顺序反了，你就会去追一群你根本服务不好的人。

把"我"拆成三类资产：

| 资产类型 | 定义 | 判据 | 格式要求 |
|---|---|---|---|
| 硬技能 | 可验证、可演示的专业能力 | 能被第三方检查：考试、作品、代码、证书 | 动词 + 对象 + 结果 |
| 软技能 | 在协作中体现的能力 | 离开具体故事就不存在 | 每条必须挂一个能讲 90 秒的故事 |
| 经历资产 | 只有时间和经历能给的 | 新人抄不走：行业年限、人脉、踩过的坑 | 提炼成"可迁移的教训" |

**格式纪律：动词 + 对象 + 结果。** 资产的价值藏在结果里，不在名词里。正反对照：

| ❌ 名词式（不可卖） | ✅ 动词 + 对象 + 结果（可卖） |
|---|---|
| 熟悉 Python | 用 Python + pandas 把每周 6 小时的对账流程自动化，降到 10 分钟 |
| 负责后端开发 | 为日均 200 万笔交易的支付系统重构对账模块，差异定位从 2 天/渠道降到 2 小时/渠道 |
| 沟通能力强 | 在财务、风控、三方支付公司之间对齐对账口径，避免一次大促前的资金对账事故 |
| 5 年电商经验 | 经历 3 次大促容量演练，沉淀出一套"大促前两周压测清单"，团队沿用至今 |
| 擅长带人 | 带 3 名初级工程师独立负责模块，其中 1 人半年后晋升 |
| 学过数据分析 | 用漏斗分析定位到注册流程第 3 步流失率异常，改版后次日留存提升 |

**经历资产的特殊格式**——它最容易被写成流水账，用这个结构提炼：

```
在 ___（情境），因为 ___（原因），踩了 ___（坑），
代价是 ___（钱/时间/机会，尽量有数字），
沉淀出规则：___（下次遇到同类情况怎么做）。
```

例：「在接入第三家支付渠道时，因为默认各家对账规则一致，踩了"渠道侧成功、我方掉单"的坑，代价是连续两个月底对账加班一周。规则：凡接新渠道，先花两天把对账规则逐条写进文档再开发。」

**软技能的纪律**：没有故事支撑的软技能不算存在。"沟通能力强"谁都会写——你必须能当场讲出一个 90 秒的故事（推荐 SCQA 结构，见[课程 06](../06-沟通工具箱/README.md)），否则从清单里删掉。

### 案例：陈默的三张清单（完整示例）

陈默，31 岁，5 年后端工程师（电商支付系统），想转数据顾问。他花一个周末填完三张清单：

**硬技能（8 条）：**

| # | 动词 + 对象 + 结果 | 熟练度 | 市场供给 |
|---|---|---|---|
| H1 | 用 Java/Go 为日均 200 万笔交易的支付网关重构对账模块，把三家渠道的对账差异定位从每家 2 天压到 2 小时 | 熟练 | 少（懂支付对账的工程师本就不多） |
| H2 | 用 Python（pandas + Airflow）搭建 30 余张表的日级数据管道，运营报表从"次日上午人工跑"变为早 8 点自动送达 | 熟练 | 中 |
| H3 | 为支付接口设计幂等与重试机制，上线后连续 4 个季度重复扣款工单为零 | 熟练 | 少 |
| H4 | 排查大促期间数据库慢查询，下单接口 P99 延迟从 3.2 秒降到 400 毫秒 | 熟练 | 中 |
| H5 | 用 SQL + 脚本为财务部做月度渠道手续费核对，3 人天/月压到 0.5 人天/月 | 熟练 | 多 |
| H6 | 搭建 Grafana 监控面板 + 告警规则，故障平均发现时间从 40 分钟降到 10 分钟 | 熟练 | 中 |
| H7 | 带两名实习生把内部工单系统从零开发到上线（含权限体系） | 会用 | 多 |
| H8 | 给团队写支付对接文档并做培训，新人独立上手周期从 6 周缩短到 3 周 | 熟练 | 多 |

**软技能（6 条，每条挂一个 90 秒故事）：**

| # | 动词 + 对象 + 结果 | 故事钩子 |
|---|---|---|
| S1 | 在财务、风控、三方支付公司之间对齐一次对账口径冲突，避免大促前夜的资金对账事故 | SCQA：冲突升级→一页对照表化解 |
| S2 | 把"重构还是修补"的技术分歧写成一页决策 memo，说服 CTO 批准 6 周重构窗口 | SCQA：两次故障成本 vs 重构成本 |
| S3 | 带 3 名初级工程师独立负责模块，其中 1 人半年后晋升 | SCQA：从代写到"不review最后一行" |
| S4 | 主导一次重复扣款事故的客户沟通与复盘，把可能升级的客诉转化为客户书面感谢 | SCQA：凌晨的电话 |
| S5 | 在公司内部做 4 场技术分享，场均 60 人以上到场 | SCQA：把枯燥的对账规则讲成侦探故事 |
| S6 | 把客服团队"报表太慢"的模糊抱怨拆成 3 个可排期的明确需求 | SCQA：三轮追问找到真凶 |

**经历资产（6 条）：**

| # | 情境 + 坑 + 代价 + 规则 |
|---|---|
| E1 | 5 年电商支付系统：踩"三方渠道对账规则不一致"的坑，代价是两个月底连续加班一周 → 规则：接新渠道先写对账规则文档 |
| E2 | 经历一次大促系统崩溃：容量评估只算了均值没算尖峰 → 规则：大促前两周必须全链路压测 |
| E3 | 接过一次外包私单：范围没书面化，干了约 3 倍工作量才收到原款 → 规则：无书面范围不开工（将来做顾问的第一条军规） |
| E4 | 与风控团队的一次冲突：各自讲专业术语不欢而散 → 规则：先翻译成对方的 KPI 语言再讨论方案 |
| E5 | 人脉：认识 3 家支付渠道的技术对接人，2 位前同事在跨境电商做财务负责人（未来第一批客户来源） |
| E6 | 亲历一次业务线裁撤：看到预算被砍的完整决策过程 → 理解企业花钱的审批逻辑，知道什么时候客户"真没钱" |

注意 E3 和 E6：**失败和裁撤也是资产**——它们是"只有踩过坑才知道的事"，恰恰是客户付钱想买走的。

### 练习

填写三张清单工作表（硬技能目标 ≥ 8 条，软技能 ≥ 6 条，经历资产 ≥ 6 条）：

```
【硬技能】我问自己：我操作过什么工具/方法，解决过什么问题，结果如何？
1. 用 ___ 对 ___ 做到 ___（数字）
2. ……

【软技能】我问自己：同事和合作方为什么主动来找我帮忙？每次是为什么？
（每条后面写上故事钩子的四个词：背景/冲突/问题/结果）
1. ___ —— 故事：___
2. ……

【经历资产】我问自己：只有踩过坑才知道的事，我有哪些？
1. 在 ___，因为 ___，踩了 ___，代价 ___，规则：___
2. ……
```

诚实纪律：熟练度先按下一课的四级标准预标，市场供给凭直觉预标——第 2 课会校准它们。

### 自测

1. "熟悉 Python"为什么不算资产？"精通 Java"呢？
2. 经历资产格式的最后一步"规则"为什么必须有？
3. 判断题：失败经历不该写进清单，会显得能力不行。（对 / 错）

<details><summary>参考答案</summary>

1. 没有对象和结果，无法与另一个"熟悉 Python"的人区分，也无法定价。资产的价值在结果里。
2. 规则是经历变成"可迁移教训"的标志——客户买的就是这条规则，情境只是它的载体。
3. 错。踩坑经历 + 代价 + 规则，是新手抄不走的差异化资产，也是讲信任故事的最佳素材。

</details>

## 第 2 课：技能分级与稀缺度——四象限矩阵

### 讲解

清单是原料，这一课做分拣。每个技能标两个维度：

**维度一：熟练度（诚实自评）**

| 级别 | 判据 |
|---|---|
| 精通 | 能教别人；能处理该领域的异常与边界情况；别人会拿疑难问题来问你 |
| 熟练 | 能独立交付完整工作，不需要指导 |
| 会用 | 能在框架和指导下完成任务 |
| 了解 | 知道概念，读过文档，没做过真实交付 |

诚实地标——市场会替你校准，高标一级只会在交付时穿帮（那比"不熟练"贵得多，参见[课程 01](../01-底层认知/README.md)的品牌折旧）。

**维度二：市场供给（目标市场里有多少人也有）**

判断方法（不要拍脑袋，花 30 分钟实际查）：

1. 招聘平台上把技能当任职要求的职位多不多、竞争该职位的人多不多。
2. 垂直社区里这个话题的活跃作者数量。
3. 同类自由职业者的报价离散度：一堆人低价抢单 = 供给过剩。

**四象限矩阵：**

| | 市场供给少 | 市场供给多 |
|---|---|---|
| **熟练度高** | **A 定价主打区** | **B 组合配料区** |
| **熟练度低** | **C 战略投资区** | **D 放弃区** |

每个象限的策略：

| 象限 | 定价策略 | 组合策略 | 本周动作 |
|---|---|---|---|
| A（熟练 + 稀缺） | 价值定价，项目制起步，目标 Retainer 化；不按小时卖 | 作为组合的**主卖点**，写进 PVP 的"独特方法"句 | 加深 + 公开作品强化权威信号 |
| B（熟练 + 泛滥） | 不单独定价——单独卖只能卷价格 | 作为组合的**连接件**：它让 A 区技能交付得更快更稳，价值隐含在项目价里 | 保持，不值得额外投入 |
| C（不熟 + 稀缺） | 不定价——现在还不能卖 | 判断题：6 个月内能否练到"熟练"？能 → 列刻意练习计划，作为第二曲线储备；不能 → 移出对外主张 | 做出投资判断，写下结论 |
| D（不熟 + 泛滥） | 无 | 不出现在任何对外说法里 | 降权，不再投入 |

**新手最常见的死法**：把 C 区技能当主卖点。稀缺是真稀缺，熟练度也是真不够——客户一深问就穿帮，一次穿帮毁掉整个信任账户（见[课程 01](../01-底层认知/README.md)信任方程的专业能力项）。

### 案例：陈默的象限分拣

陈默把第 1 课清单里 8 项硬技能落进矩阵：

| 技能 | 熟练度 | 供给 | 象限 | 处理 |
|---|---|---|---|---|
| H1 支付对账系统 | 熟练 | 少 | **A** | 主卖点候选 |
| H3 幂等与重试机制 | 熟练 | 少 | **A** | 主卖点候选（与 H1 同族，可合并叙事） |
| H2 数据管道 | 熟练 | 中 | A/B 之间 | 视目标行业定：配跨境电商 = 偏 A，配泛行业 = B |
| H4 性能优化 | 熟练 | 中 | B | 连接件 |
| H6 监控体系 | 熟练 | 中 | B | 连接件 |
| H5 SQL/核对脚本 | 熟练 | 多 | B | 配料 |
| H8 文档与培训 | 熟练 | 多 | B | 配料（交付时省沟通成本） |
| H7 带实习生做全栈 | 会用 | 多 | D | 不对外 |

**陈默走过的弯路**：他最初想把"大模型应用"当主卖点——AI 咨询听起来稀缺又时兴。按四象限一查：他的实际熟练度是"了解 + 做过两个 demo"，而市场供给正在快速增加（招聘职位数、社区作者数每月可见地涨）。结论：C 区都算不上，滑向 D。他把它从 PVP 里删了，只留作个人学习兴趣。这个"忍住不蹭热点"的动作，帮他避免了"客户深问三句就露馅"的结局。

### 练习

1. 给第 1 课清单里的每条硬技能标注：熟练度四级 + 供给三档（多/中/少）+ 落入哪个象限。
2. 供给标注必须有一个实际查证动作（招聘平台搜索记录 / 社区浏览记录），写下你查了什么、看到了什么。
3. 写出你的 A 区技能清单（0–3 项都正常），以及每个 C 区技能的"6 个月投资判断"。

### 自测

1. 为什么 B 区技能"单独卖只能卷价格"？
2. 你有一项"了解"级的稀缺技能，客户问起时该怎么回答才不穿帮？
3. 判断题：A 区技能越多越好，应该把所有 B 区技能都练成 A。（对 / 错）

<details><summary>参考答案</summary>

1. 供给多意味着可替代者众，客户比价的成本极低，价格成为唯一竞争维度。
2. 如实定位："这块我做过 X，还没到能独立交付的程度——如果是核心需求，我建议找 ___，或者我把它作为学习项配合主方案做。"诚实反而加分（降低自我导向）。
3. 错。资源有限，A 区靠深度不靠数量；B 区的价值恰恰是给 A 区当连接件，组合见第 3 课。

</details>

## 第 3 课：组合优势 Skill Stack——三维矩阵法

### 讲解

单技能做到全国前 1% 极难；但把两三个各自前 25% 的技能组合起来，你可能在一个交叉点上进入前 1%——因为同时具备的人极少。这一思路来自 Scott Adams 的 "talent stack"。直觉上也好理解：每一项都不那么稀有的人，交集却骤减——而市场为"能一个人解决一整类问题"的组合支付溢价。

**怎么系统地找组合，而不是等灵感？用"技能 × 行业 × 人群"三维矩阵法：**

```
操作步骤（全程约 2–3 小时，用一张表格或三个白板列完成）：

第 1 步 列「技能」维：从第 2 课的 A 区全部 + B 区挑 2–3 项，共 4–6 项技能/领域知识。
第 2 步 列「行业」维：写下你有过真实接触的行业——雇主所在行业、服务过的客户、
        行业里的人脉（4–6 个）。
第 3 步 列「人群」维：写下你能触达、且大概率有钱有痛的角色（4–6 个）。
        注意是"角色"不是"公司"：跨境电商的财务负责人，而不是"跨境电商公司"。
第 4 步 填交叉格：对每个「技能×行业」组合，问"这个行业里，这个技能对应什么具体问题？"
        再对每个结果问"这个问题晚上睡不着的是哪个人群？"
第 5 步 初筛：标出 3–5 个"我有料（A/B 区技能撑得住）+ 有人痛（说得出具体麻烦）
        + 碰得到（人群在我的触达范围内）"的格子。
第 6 步 跑稀缺度三问（见下），淘汰不合格的。
第 7 步 留下 ≥ 3 个候选，带进第 4 课写 PVP——让市场检验，而不是自己拍板。
```

**交叉点稀缺度三问的操作细节：**

| 问题 | 具体操作 | 判据 |
|---|---|---|
| 问 1：同时具备的人多吗？ | ① 招聘平台双关键词同搜（如"支付 + 对账"），看要求同时具备的职位量与急迫度；② 内容平台搜交叉关键词，数持续产出者人数；③ 问 3 个业内朋友"你认识同时懂 X 和 Y 的人吗"，记录能数出的名字 | 交叉职位多且难招、内容产出者一只手数得过来、朋友数不出 5 个名字 → 稀缺 |
| 问 2：交叉点有真实需求吗？ | ① 找付费证据：有没有公司为这个交叉挂职位、发预算、发招标；② 找"硬扛"证据：目标人群是否在用人工+表格+加班硬顶；③ 找竞品证据：是否已有人卖类似交叉服务且活得不错 | 三者任一成立即算有需求；有竞品是**好**信号（市场被验证），别怕 |
| 问 3：能讲清 1+1 为什么 >2 吗？ | ① 30 秒录音："同时懂 X 和 Y 的我，比分别请两个专家，好在哪？"② 让一个外行听完转述，看是否走样；③ 填空："因为 X 我能___；因为 Y 我能___；同时拥有，我能___（别人做不到）" | 三个空填不满、外行转述走样 → 回炉，这个交叉还没长熟 |

**五种高价值交叉模式**（每个配两个真实感人物——均为虚构示例，方法才是重点）：

**模式一：领域 × 技术**

- 林芝：8 年四大会计 + 自学 Python。专帮年营收 1–10 亿的制造企业做月末结账自动化。1+1：她不需要工程师做翻译——会计科目和代码在她脑子里是同一种语言，沟通成本为零，而"翻译"正是这类项目最贵的隐性成本。
- 赵航：结构工程师出身转写代码，专做第三方检测实验室的报告自动化。1+1：他知道检测规范哪一条对应哪个字段，写出来的系统直接过审，纯技术团队要反复返工。

**模式二：领域 × 表达**

- 沈一帆：三甲医院药师，做用药安全科普。1+1：内容泛滥的时代，"在职药师"是稀缺的可靠信源，变现走药企合规培训与平台专栏，客户从读者里自然长出来。
- 何蔓：涉外律师，给跨境电商卖家写欧美合规系列。1+1：法律服务的获客成本极高，而持续的内容让客户带着信任上门，她的询盘几乎零成本。

**模式三：技术 × 审美**

- 陆遥：前端工程师 + 设计系统经验，卖"设计系统落地"服务。1+1：品牌升级后的公司最怕设计与开发两张皮，他一个人闭环，减少两个团队的 handoff 损耗。
- 简宁：数据分析师，专做"高管愿意看完的报告可视化"。1+1：她的卖点不是图表好看，是"能在董事会上通过"——懂得在信息的哪一层给结论、哪一层给细节。

**模式四：经验 × 新技术**

- 老金：15 年纺织外贸 + AI 工具，做中小外贸厂的选品与询盘自动化顾问。1+1：他 know 工厂的账怎么算、老板怕什么，AI 只是他手里的新扳手——纯 AI 背景的顾问说不出"这个SKU的打样成本"。
- 孟真：放射科技师 + AI 阅片工作流咨询。1+1：她懂排班、质控和临床路径，知道 AI 结果怎么嵌进医生的工作流才真的被用起来，而不只是演示好看。

**模式五：技能 × 语言 / 地域**

- 方远：国内供应链采购经验 + 日语，服务日企在华工厂的降本审计。1+1：既懂国内供应商的报价水分，又能用日语向总部汇报，两地信息差就是他的护城河。
- 夏彤：在欧洲工作 5 年的产品经理，帮国内 SaaS 做出海 GTM 顾问（定价、合规、渠道）。1+1：她踩过的坑，客户每个都要踩一遍——除非买她的坑图。

### 案例：陈默的三维矩阵

陈默的三维列表：技能维 = 支付对账领域知识（A）、幂等与资金安全（A）、数据管道（A/B）、性能优化（B）；行业维 = 跨境电商、本地生活连锁、在线教育、SaaS 公司；人群维 = 财务负责人/CFO、运营负责人、CTO/技术负责人、中小品牌创始人。

填交叉格（节选）：

| 技能 × 行业 | 对应的具体问题 | 睡不着的人群 |
|---|---|---|
| 支付对账 × 跨境电商 | 多币种、多渠道（PayPal/Stripe/收单行）对账差异与资金滞留 | 财务负责人（月底人天爆炸、差错要自己背） |
| 数据管道 × 在线教育 | 投放数据分散在 5 个平台，ROI 报表靠人工拼 | 运营负责人 |
| 性能优化 × SaaS | 大客户投诉系统慢，续约受威胁 | CTO |
| 支付对账 × 本地生活连锁 | 三方外卖平台佣金核对，差异频繁 | 财务负责人（但决策链慢、预算小） |

初筛后留 3 个候选，跑三问：

| 候选 | 问 1 稀缺吗 | 问 2 有付费需求吗 | 问 3 讲得清吗 | 结论 |
|---|---|---|---|---|
| ① 对账自动化 × 跨境电商 × 财务负责人 | 双搜"支付+对账"职位少而急；懂支付的工程师极少愿意做乙方 | 招聘平台有公司挂"支付对账专家"职位；财务在用 Excel+加班硬扛 | "懂规则才能写对引擎，懂工程才能落地系统"——30 秒讲得清 | **主推** |
| ② 数据管道 × 在线教育 × 运营负责人 | 中等：数据工程师不少，懂投放语义的少 | 有预算但项目制居多 | 讲得清，但差异化弱 | 备选 |
| ③ 性能优化 × SaaS × CTO | 弱：性能专家供给不少 | 有付费 | 讲不出 1+1 | 淘汰 |

陈默选定 ①：三个理由——痛点最容易量化（第 1 课 H1 的"2 天 → 2 小时"就是现成弹药）、供给真的少、他自己讲得清（有故事）。候选 ② 保留，作为第二曲线。

### 练习

1. 完成自己的三维矩阵工作表：

```
技能维（A 区全部 + B 区 2–3 项）：___
行业维（有真实接触的 4–6 个）：___
人群维（可触达且有痛有钱的角色 4–6 个）：___

交叉格（至少填 8 格）：
技能 ___ × 行业 ___ → 具体问题 ___ → 睡不着的人群 ___
……

初筛（3–5 个）+ 稀缺度三问记录：
候选 1：问1 证据___ / 问2 证据___ / 问3 录音了吗___ → 结论 ___
```

2. 三问的每一问都要留下你**实际查证**的记录（搜索了什么关键词、问了谁）。没有查证记录的结论视为没做。

### 自测

1. "技能 × 行业 × 人群"里，为什么人群必须是角色而不是公司？
2. 发现已经有人在卖你的目标交叉点服务，该换方向吗？
3. 三问里哪一问淘汰的是"技术上稀缺但没人付钱"的组合？

<details><summary>参考答案</summary>

1. 公司没有痛觉，角色才有 KPI、有半夜的焦虑；且触达、提案、成交都是对着具体角色发生的。
2. 不该。竞品存在说明市场被验证过（问 2 的好信号）；该研究他的定价与短板，做出差异化。
3. 问 2（有真实需求吗）。技术自嗨的组合通常死在这里。

</details>

## 第 4 课：PVP 个人价值主张——模板逐句拆解与打磨

### 讲解

组合优势找到后，要压缩成一句话让市场秒懂——PVP（Personal Value Proposition）。模板：

> 我帮助 **[具体人群]**，用 **[独特方法/技能组合]**，在 **[时间框架]** 内实现 **[可衡量结果]**，而且 **[不需要他们担心的事]**。

逐句拆解——每一句都承担一个不可替代的功能：

**第 1 句：具体人群。**
存在的理由：让听者在 3 秒内完成"是不是在说我"；同时为你的触达划定名单（这句直接喂给[课程 03](../03-市场与客户/README.md)的 ICP）。人群的本质是 JTBD——你帮他们完成什么任务。

> ❌ 写错的典型样子："帮助有数字化需求的企业。"（没有人会对号入座）
> ✅ 写对的判据：人群能被画出画像（职业、公司规模、场景），且你能说出他们深夜的焦虑。

**第 2 句：独特方法/技能组合。**
存在的理由：这是你的交叉点，是竞争对手复述不出来的部分——PVP 的差异化全押在这句。

> ❌："用专业的服务、丰富的经验……"（废话，人人能说）
> ✅：方法有名字、有结构、有你独有的原料（如"支付系统工程经验 + 三年积累的渠道对账规则库"）。

**第 3 句：时间框架。**
存在的理由：让承诺变得可检验，也提前修剪不合理的期待（客户对你的耐心是有期限的）。

> ❌："从根本上、长周期地提升……"（不可检验 = 不负责任）
> ✅："在一个结账周期内（约 4 周）"——到期就能对账。

**第 4 句：可衡量结果。**
存在的理由：价值的度量衡。没有这句，价格谈判就没有参照系（客户拿什么判断你值 3 万还是 30 万？）。

> ❌："显著提升效率。"（显著是多显著？）
> ✅："把三家支付渠道的月度对账人工从 3 天压到 2 小时。"（有基线、有终点）

**第 5 句：不需要他们担心的事。**
存在的理由：直接拆除客户价值等式里最大的那颗雷（见[课程 01](../01-底层认知/README.md)——风险项经常比价格更致命）。这句是写给签字那个人的。

> ❌：写成又一个卖点："而且我们服务特别贴心。"（雷没拆，废话+1）
> ✅：对准真实顾虑："不需要动现有 ERP、不需要招技术岗。"（前提：你真的知道他们在担心什么）

**打磨 PVP 的 5 个迭代问题**（每一版都过一遍）：

1. **删人群测试**：把人群限定词删掉，这句话还成立吗？成立 = 写得太泛，回去收窄。
2. **对手复述测试**：想象你最直接的竞争对手原样念你的 PVP——有任何违和吗？"这话他也能说"= 方法句没写出交叉点。
3. **KPI 语言测试**：结果句是客户会写进自己周报/考核的语言，还是你的专业黑话？"P99 延迟降低"不如"大促期间下单不再卡单"。
4. **真雷测试**："不需要担心的事"是你**问过至少 3 个目标客户**后确认的顾虑，还是你猜的？猜的要换成问出来的。
5. **追问测试**：这句话能换来一句"你怎么做到的？"吗？换不来 = 没有钩子，方法句太平。

**差异化检验法（三连测，通过才算数）：**

| 检验 | 操作 | 通过标准 |
|---|---|---|
| 对手复述测试 | 扮演竞品念你的 PVP | 有明确违和感（"这不是我的东西"） |
| 替换测试 | 把你的名字换成任何一个同行 | 句子立刻不成立（主角只能是你的交叉点） |
| 外行转述测试 | 讲给非业内朋友，请他转述给第三者 | 转述不走样（说明真的听得懂、记得住） |

### 案例：陈默的 PVP 三版迭代

> **v1**："我是一名资深数据顾问，帮助企业提升数据效率，实现降本增效。"
> 迭代问题 1、2 全挂：删掉人群照样成立；任何同行可原样复述。这不是 PVP，是工种介绍。

> **v2**："我帮助跨境电商团队，用数据分析 + 自动化的组合，在一个月内把月度对账从 3 天压缩到 2 小时，不需要额外招聘技术岗。"
> 问题 2 部分通过，问题 1 挂：'团队'仍泛（老板？运营？财务？）；"数据分析+自动化"是个筐，交叉点没露出来。

> **v3**："我帮助跨境电商的财务负责人，用'支付系统工程 + 渠道对账规则库'的组合，在一个结账周期内把多渠道对账的人工从 3 天压到 2 小时——不需要动现有 ERP，也不需要招技术岗。"
> 五问全过：人群可画像；方法竞品复述不了（规则库是他的独有原料）；周期可检验；结果带基线；"不动 ERP、不招人"是他在两个目标客户那里问出来的真雷。

v3 仍不是终点——PVP 是活文档，每季度随市场与案例重新迭代（见[课程 08](../08-度量与复盘/README.md)的复盘节奏）。

### 练习

1. 写出你的 PVP v1（哪怕很烂，先有靶子）。
2. 找 3 个目标客户或贴近日标客户的同行，问两个校准问题："这件事你们现在最头疼的是什么？""如果有人能解决，你最担心什么？"把答案落回第 4、5 句。
3. 迭代出 v2，跑三连测，记录每一测的原始反馈（谁的复述、谁的转述）。

### 自测

1. PVP 第 5 句"不需要担心的事"直接对准课程 01 哪个公式的哪一项？
2. "我帮助中小企业用 AI 实现数字化转型"——至少指出两处问题。
3. 为什么 PVP 需要每季度重新过一遍三连测？

<details><summary>参考答案</summary>

1. 客户价值等式的"决策风险"（及迁移麻烦）项——它拆的是签字人的雷。
2. 人群无画像（中小企业是什么）；方法无交叉（AI+数字化转型是新闻语言不是方法）；无可衡量结果；无时间框架；无风险拆除——五句里四句不合格。
3. 市场供给、你的案例库、客户顾虑都在变；PVP 的差异化是相对竞品的动态关系，不是一次性认证。

</details>

## 第 5 课：30 秒电梯陈述——PVP 的场景化发射

### 讲解

PVP 是文字稿，电梯陈述是它的口语发射装置。结构：**PVP 浓缩 + 一个数字化案例 + 一个反问**。

逐句拆解（以 30 秒为预算）：

| 句 | 时长 | 功能 | 判据 |
|---|---|---|---|
| 1 身份锚 | ~5 秒 | 不是职位，是"我帮谁解决什么" | 对方听完能把你归档到一个具体问题上 |
| 2 证据 | ~15 秒 | 最强的一个数字案例（SCQA 压缩：情境→冲突→我做了什么→数字） | 有基线有终点，20 个字内讲完 |
| 3 反问 | ~8 秒 | 把话题交回对方，探测需求 | 问的是对方现状，不是"你需不需要我" |
| 4 出口（可选） | ~5 秒 | 视对方反应给一个低门槛下一步 | 答应成本极低（加微信、发个案例链接） |

**为什么必须有反问？** 没有反问的自我介绍是广告，有反问才是对话。反问还完成一次身份转换：把对方从"评估你的人"变成"审视自己问题的人"——后者的心理姿态对你有利得多（呼应[课程 01](../01-底层认知/README.md)：好的销售让客户觉得是自己想清楚的）。

**三个场景版本的设计差异**：

| 场景 | 对方心理 | 设计要点 | 禁忌 |
|---|---|---|---|
| 社交场合 | 放松、防推销雷达全开 | 行话归零，只留"帮谁解决什么脏活累活"；反问要像聊天不像开场白 | 提"服务""合作""方案"等销售词汇 |
| 求职面试 | 评估风险与协作成本 | 证据句对准雇主的 KPI；补一个稳定性/协作信号；反问变成对团队痛点的真诚提问 | 背简历；把面试官当客户推销 |
| 客户提案 | 已有基本认知，评估可行性 | 最完整版：现状→新状态→证据→风险拆除一句带过；结尾给具体下一步 | 30 秒塞进报价细节 |

**交付纪律**：写完必须录音回听。几乎所有人第一次都说超 60 秒——删到 35 秒以内才算合格。听录音时检查三件事：秒数、有没有钩子（对方会追问什么）、反问是否自然。

### 案例：陈默的三版电梯陈述

**社交场合版**（行业聚会上，有人问"你是做什么的"）：

> "我原来是写支付系统的，现在专门帮跨境电商搞定对账这种脏活——你知道好几个渠道的账对不上是什么感受吧？我上一个客户，每月底仨人核三天，现在俩小时。（反问）你们公司这块是谁在管？"
>
> 设计注释："脏活"是社交语言不是销售语言；数字案例 20 字内；反问顺走聊天节奏。对方大概率接"我们财务好像也在搞这个"——钩子生效。

**求职面试版**（面试官："介绍一下你自己"）：

> "我做了 5 年电商支付系统，最拿手的是对账和资金一致性——上一家公司三家支付渠道的月度对账，从我接手时的每家 2 天压到 2 小时，重复扣款连续四个季度零工单。我很习惯跟财务、风控这种非技术团队配合，因为对账这活儿一半是工程，一半是口径翻译。（反问）想问一下，团队这边数据和对账目前最需要人搭把手的是哪块？"
>
> 设计注释：证据对准雇主 KPI（稳定性、跨团队协作）；"口径翻译"展示软技能；反问把话题引向团队痛点——面试官的回答就是他后面回答的靶子。

**客户提案版**（跨境电商业内分享后的茶歇，财务总监主动来聊）：

> "刚才您说月底要核三家渠道的账——我做这个做了五年，规则库里有三十几类常见的渠道差异。做法是先拿你们一个品类做两周试点，跑通了对账从 3 天到 2 小时是什么样，再决定要不要铺开，不动你们 ERP。（反问）你们现在月底对账是几个人几天？"
>
> 设计注释：证据 + 风险拆除（试点、不动 ERP）各一句；反问在收集深谈要用的基线数字——这句陈述本身就是一次微型 SPIN 开场（见[课程 04](../04-销售全流程/README.md)）。

### 练习

1. 按 4 句结构写出你的三版电梯陈述。
2. 每版录音，回听打分：秒数（≤35）/ 钩子（预判对方会追问什么）/ 反问自然度。
3. 找一个人（朋友或 AI 均可）扮演三种场景的听众，实测有没有换来追问。没有追问就改证据句——通常问题出在数字不具体。

### 自测

1. 反问句为什么不能问"您有这方面的需求吗"？
2. 面试版为什么把"稳定性与协作"放进证据句，而不是说"我很稳定、善于合作"？
3. 判断题：电梯陈述背得越熟越好，滚瓜烂熟显得专业。（对 / 错）

<details><summary>参考答案</summary>

1. 这是封闭式问题，答案只有"有/没有"，且把对方推回评估者位置；问现状（"你们现在怎么做"）才能开启对话并拿到信息。
2. 形容词不可信，事实自带属性——"重复扣款连续四个季度零工单"就是稳定性的证明（FABG 里的 F 与 B，见课程 04）。
3. 错。背熟的痕迹会触发"推销"雷达；练到"结构在、语言每次不一样"才是合格状态。

</details>

## 第 6 课：证据资产——让主张变成事实

### 讲解

PVP 是主张，市场对主张的默认反应是不信。证据的作用是把主张变成事实——它同时喂饱两台心理机器：权威（公开的方法与作品）和社会认同（同类客户的案例），见[课程 01](../01-底层认知/README.md)。

**四种证据的说服力排序与使用场景：**

| 排序 | 类型 | 说服力来源 | 最适用场景 | 使用要点 | 常见坑 |
|---|---|---|---|---|---|
| 1 | 量化结果 | 数字 + 前后对比，可复核 | 提案、报价、谈判 | 必须带基线（"从 X 到 Y"）和时间范围 | 用无基线百分比（"提升 300%"——从多少到多少？） |
| 2 | 作品 | 可点开验证的实体：代码仓库、方案文档、分析报告、文章 | 冷触达、Inbound、面试 | 链接可访问、有 README、有上下文 | 无人维护的死链、无说明的裸仓库 |
| 3 | 第三方证言 | 别人替你说话 | 决策后期、客户犹豫时 | 具名 + 具体 + 带数字 | 全是形容词的客套话（"合作非常愉快"） |
| 4 | 资历信号 | 平台背书 | 初次接触的前 30 秒 | 一两个最强的即可 | 堆砌头衔与证书，不给前三种 |

**组合拳**：一份好提案里四层证据都出现，但位置不同——资历开头露脸，量化结果撑中段，证言放在风险讨论处，作品放附录供深挖。单一证据孤军作战，说服力叠加不起来。

**证据库的复利机制**：每完成一个项目（无论大小），强制产出三件套——1 个新数字、1 段证言、1 个可展示作品——并做一次 AAR 复盘（见[课程 08](../08-度量与复盘/README.md)）。这是你长期最重要的库存，比任何营销动作都值钱。

**零基础怎么办？三条积累第一个案例的正当路径：**

**路径一：低价试点。**
- 适用：已有一定人脉或专业积累，缺的是"个人交付"的记录。
- 操作步骤：①对象从熟人推荐里选（有真实痛点、规模中小、决策链短）；②明说这是试点价及原因（"我在做这个行业案例，试点价 4–6 折"——不隐瞒，隐瞒即埋雷）；③书面定义可量化的成功指标；④超预期交付（主动多做一件计划外的小事）；⑤结项当天要三样东西（见下方条款）；⑥第二次合作按标准价，且写进本次协议。
- 必须换到的东西（一条都不能少）：

```
【试点合作条款要点（可直接改写进协议）】
1. 范围：仅 ___，明确不含 ___（防范围失控）
2. 价格：试点价 ___（标准价约 ___，写明差额逻辑）
3. 试点价交换条件（三者全有）：
   a. 达标后可公开公司名与脱敏数据的书面授权
   b. 一段具名证言（含具体数字）
   c. 转介绍 2 位同类负责人
4. 成功指标：___（可测量、有时限）
5. 后续合作按标准价目执行（写进条款，防"永久试点价"）
6. 超出范围的需求按变更单评估
```

- 风险与对策：被当成廉价劳动力、试点完只肯续试点价 → 靠条款 5 挡住，对方不接受就说明他买的从来不是价值，及时止损；范围失控 → 靠条款 1 和 6 挡住。

**路径二：免费换案例与授权。**
- 适用：连试点价都卖不动的完全冷启动（转行、无作品、无人脉）。
- 操作要点：免费 ≠ 无条款。照样签一份"零元合同"，写清范围、时限（建议 ≤ 2 周/20 小时）、双方义务，以及必须换到的三样：数据公开授权、具名证言、或 2 个转介绍。对象优先非营利组织、朋友的公司（前提：问题真实存在，不是给你练手的道具）。
- 风险与对策：免费的东西不被珍惜、需求无限发散 → 合同与范围照常执行，你放弃的只是价格，不是专业姿态；吓坏未来的付费客户 → 对外统一口径："每年我只做 2 个开门案例，今年的名额已满。"

**路径三：公开作品替代。**
- 适用：接触不到愿意配合的真实客户，或想先验证选题。
- 操作步骤：①选一个目标人群真痛的问题（先问 3 个目标客户"这个你们在乎吗"，防自嗨）；②产出可验证的作品——真实公司公开问题的拆解分析（措辞是"分析"不是"评判"）、开源工具 + 文档、公开数据集的分析报告、系统化教程；③在目标人群出没的渠道发布；④每个作品配一段 SCQA 叙事，并附"我为什么能做这个"的方法说明。
- 风险与对策：自嗨选题 → 第 ① 步的前置访谈挡住；只有作品没有叙事 → 流量来了留不下"你能帮我"的印象。公开作品同时是 Inbound 引擎的起点（见[课程 04](../04-销售全流程/README.md)），一鱼两吃。

**选择决策**：有人脉可借力 → 路径一或二；完全冷启动 → 路径三先行，同步预热路径一。三条路径都要求一个底线：**不虚构任何数字与客户**——证据造假被拆穿一次，信任方程的分母趋向无穷大，这个账号就废了。

### 案例：陈默的第一个案例

陈默通过 E5 人脉（前同事在跨境电商做财务负责人）拿到第一个机会：一家 60 人的跨境电商公司，PayPal + Stripe 两条渠道的月度对账常年 3 人天。他走路径一：报价 12,000 元（他自评标准项目价约 30,000 元），签了上面那份试点条款。

- 两周交付：对账规则入库 + 自动化脚本 + 差异报表；计划外多做了一件小事——给财务做了一次 40 分钟的规则讲解培训（超预期时刻）。
- 结果：连续两个结账周期对账人工 ≤ 0.5 人天/月（条款 4 达标）。
- 换到：具名证言一段（"陈默把我们的月度对账从 3 人天压到半天以内，中间发现的 2 笔渠道差异追回了 4 千多美金"）+ 公开授权 + 2 个转介绍。
- 三个月后：其中一条转介绍成交第二单，按标准价 38,000 元——条款 5 让这次报价没有遭遇"你上次不是 1 万 2 吗"的灵魂拷问。
- 复盘（AAR）：他把"先讲对账规则、再谈自动化"确认为自己的提案顺序，写进了后来的提案模板。

注意这个案例的因果链：**低价买到的是证据与授权，不是收入**——第一单的意义在于让第二单可以按标准价成交。

### 练习

1. 证据库存量盘点：

```
【证据库存量表】
量化结果：___ 个（每个有基线吗：Y/N）
作品：___ 个（链接都活着吗：Y/N；有叙事吗：Y/N）
第三方证言：___ 段（含数字几段）
资历信号：最强的 1–2 个：___
最弱的一环是第 ___ 类，因为它 ___
```

2. 制定"第一个证据"行动计划：选定路径（一/二/三），写出 14 天内的动作清单（对象名单、要发的消息、要产出的作品），并抄一份对应的条款/合同要点。

### 自测

1. 为什么量化结果必须带基线（"从 X 到 Y"）而不是只报"提升了 Z%"？
2. 试点结束后客户说"下个月继续按这个价来"，你该怎么回应？
3. 判断题：零基础时先免费做三个项目，攒够了案例再谈收费。（对 / 错）

<details><summary>参考答案</summary>

1. 无基线的百分比无法估值：从 1 到 3 和从 10000 到 30000 都是"提升 200%"，客户没法据此判断你值多少钱。
2. 引用协议条款 5："试点价是第一次合作的约定，当时说好后续按标准价目。这次项目我会比试点多做 ___。"——守住锚点，用增量价值而不是让步换续约。
3. 错。免费也要限量、换条件（路径二的纪律）；连做三个免费，你训练的是市场"你不值钱"的预期。

</details>

## 过关标准

- [ ] 三张资产清单完成：硬技能 ≥ 8 条、软技能 ≥ 6 条（每条挂故事钩子）、经历资产 ≥ 6 条（情境+坑+代价+规则），全部动词 + 对象 + 结果格式。
- [ ] 每条硬技能完成四象限定位（含至少一个实际查证的供给证据），A 区清单与 C 区投资判断成文。
- [ ] 三维矩阵跑完，≥ 3 个候选组合通过稀缺度三问（每问留有查证记录）。
- [ ] PVP 完成且通过三连测（对手复述 / 替换 / 外行转述），有至少 3 个目标客户的校准记录。
- [ ] 三版电梯陈述（社交 / 面试 / 提案）录音完成，每版 ≤ 35 秒，至少一版实测换来了追问。
- [ ] 证据库存量盘点完成 + "第一个证据"14 天行动计划成文（含选定路径与条款要点）。

## 常见错误

- **清单写成职责描述**："负责后端开发"是岗位说明书，不是资产；没有对象和结果，市场无处定价。
- **把 C/D 区技能当主卖点**：稀缺但撑不住深问，一次穿帮毁掉整个信任账户。
- **跳过三问的第 2 问**：技术上很酷、没人付钱的交叉，是自我感动重灾区。
- **PVP 写成愿景口号**："助力企业数字化转型"——删掉你的名字句子依旧成立，等于没写。
- **电梯陈述 60 秒停不下来**：证据句塞了三个案例；一个最强的就够。
- **免费干活没换任何东西**：放弃了价格不等于放弃条款；授权、证言、转介绍，一样都要落纸面。
- **证据注水**：编数字、借案例。被拆穿一次，个人品牌的残值为零。
